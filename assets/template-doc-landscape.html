三件事让我换掉 Markdown

Agent 输出文档这件事，最近发生了三个变化 —— 任何一个都让 Markdown 显得不够用了。

SHIFTS · 3
  • 表达力。Agent 越强，Markdown 的结构反而越像约束 —— 想要表格、SVG、动画、interactive 都得绕。
  • 读完率。100 行以上的 .md 没人会读完，包括我自己。组织里更不会有人去读。
  • 编辑权。我不再亲自改 spec —— 都让 Claude 改，Markdown "易于手编辑" 这条优势也消失了。

§ 02 · WHY HTML

六条理由，按强弱排

从最功能性的（信息密度）到最主观的（快乐）—— 都是 Thariq 实操后的判断。

REASONS · 6
01 · DENSITY

信息密度

表格、CSS、SVG、代码、交互、空间数据 —— 几乎任何 Claude 能读的信息都装得下。

02 · CLARITY

视觉清晰

不再 100 行就劝退，用 tab、链接、插图分层；移动端能响应式重排。

03 · SHARING

易于分享

上传 S3 拿一个链接 —— 同事点开就读，比 .md 当附件读率高 10 倍。

04 · INTERACTION

双向交互

slider/knob 调参 + "复制为 prompt" 按钮 —— UI 操作直接喂回 Claude，闭环。

05 · CONTEXT

数据吸纳

Claude Code 能扫代码库 + 接 MCP（Slack/Linear）+ 读 git 历史 + 用浏览器。

06 · JOY

快乐

做 HTML 让人更投入，更觉得"我做的"，而不是"agent 做的"。

§ 03 · IN PRACTICE

五个用法 + 一个起手式

每条都附 Thariq 原 prompt 改写，直接抄 — 别先去写 skill。

USE CASES · 6

Specs / 规划 / 探索

01 · MOCKUP GRID

不确定方向时，让 agent 给 N 个选择并排放 —— 用"指着选"代替"读完三段长文再脑补"。

Generate 6 distinctly different approaches — vary layout, tone, density. Lay them out as a single HTML grid. Label each tradeoff.

代码评审

02 · ANNOTATED DIFF

diff 是空间信息，Markdown 把它压扁了。让 agent 渲染带边距批注 + 严重度配色的 HTML。

Help me review this PR. Render the diff with inline margin annotations, color-code findings by severity.

设计 / 原型

03 · TUNER

动效和交互不能用文字描述 —— 一个带 slider 的临时页面 5 秒讲清楚一段话讲不明白的事。

Create an HTML file with sliders for animation duration and easing. Add a copy button to export the parameters.

报告 / 调研 / 学习

04 · INTERACTIVE EXPLAINER

跨多源综合（代码 + git + Slack + 网页）产 explainer，是 Claude Code 比 ClaudeAI / Design 强的地方。

Read the rate limiter code. Produce a single HTML explainer: token-bucket diagram, 3-4 key snippets annotated, gotchas section.

临时编辑器

05 · THROWAWAY UI

Prompt box 里描述不清的事，让 agent 给你做一次性的 purpose-built 小 UI，最后导出回 prompt。

Make me an HTML file with each ticket as a draggable card across Now / Next / Later / Cut. Add "copy as markdown" button.

起手式 · 别先去写 skill

06 · JUST PROMPT IT

原话："我有点担心大家看完去搞个 /html skill。不需要做那么多 —— 直接说 "做个 HTML 文件"。先 prompt 几次找感觉，再考虑写 skill。"

§ 04 · FAQ

常见的"是不是太……"

Thariq 在 FAQ 章节直接回答的 6 个问题。

Q & A · 6
是不是更费 token？
确实更费。但 表达力换来的"被读完"是更大的 ROI。配合 Opus 4.7 的 1M context，多用的 token 几乎感受不到。
HTML 比 Markdown 慢多少？
慢 2–4×。但效果值得。原话："This does take longer! But I've found the results are worth it."
怎么打开 / 怎么分享？
浏览器本地直接打开（让 Claude open 它），或者 上传 S3 拿 URL 做 sharable link。
HTML diff 是不是更难做版本控制？
是。这是最大的缺点。 比 Markdown diff 更 noisy、更难 review。Thariq 没有 silver bullet，明确说这条是 tradeoff。
怎么让 HTML 不丑 / 符合公司审美？
frontend design plugin 有帮助。要贴公司 style，让 Claude 扫一遍代码库做一份 design system HTML 当参考，其他 HTML 文件都引用它。
那 Markdown 你完全不用了吗？
原话："I have honestly stopped using markdown altogether for almost everything, but I'm probably far on the HTML maximalist side of things."
