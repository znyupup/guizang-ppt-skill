USING CLAUDE CODE · ESSAY 01

HTML 比 Markdown 更有效

Thariq @trq212 · Anthropic · Claude Code · 9.5M views · 13.7K likes
TL;DR
Markdown 在膨胀，HTML 在崛起。Agent 越强，Markdown 的表达力越像约束。 切到 HTML 后，spec 变得能读、能交互、能分享 —— 而且我比以前更觉得自己在 loop 里。
§ 01 · THESIS

三件事让我换掉 Markdown

Agent 输出文档这件事，最近几个月发生了三个变化 —— 任何一个都让 Markdown 显得不够用了。

  • 表达力。Agent 越强，Markdown 的结构反而越像约束 —— 想要表格、SVG、动画、interactive 都得绕。
  • 读完率。100 行以上的 .md 没人会读完，包括我自己。组织里更不会有人去读。
  • 编辑权。我不再亲自改 spec —— 都让 Claude 改，Markdown "易于手编辑" 这条优势也消失了。
"Markdown has become a restricting format." — Thariq
§ 02 · WHY HTML

六条理由，按强弱排

从最功能性的（信息密度）到最主观的（快乐）—— 但都是 Thariq 实操后的判断。

01 · DENSITY

信息密度

表格、CSS、SVG、代码、交互、空间数据 —— "几乎任何 Claude 能读的信息" 都装得下。

02 · CLARITY

视觉清晰

不再 100 行就劝退，用 tab、链接、插图分层；移动端能响应式重排。

03 · SHARING

易于分享

上传 S3 拿一个链接 —— 同事点开就读，比 .md 当附件读率高 10 倍。

04 · INTERACTION

双向交互

slider/knob 调参 + "复制为 prompt" 按钮 —— UI 操作的结果直接喂回 Claude，闭环。

05 · CONTEXT

数据吸纳

Claude Code 能扫代码库 + 接 MCP（Slack/Linear）+ 读 git 历史 + 用浏览器，全能进 spec。

06 · JOY

快乐

做 HTML 让人更投入，更觉得"我做的"，而不是"agent 做的"。这条本身就是理由。

§ 03 · IN PRACTICE

五个用法 + 一个起手式

每条都附 Thariq 的原 prompt 改写。直接抄，不需要写 skill。

Specs / 规划 / 探索

01 · MOCKUP GRID

不确定方向时，让 agent 同时给 N 个选择，并排放在一页里 —— 用"指着选"代替"读完三段长文再脑补"。

I'm not sure what direction to take the onboarding screen.
Generate 6 distinctly different approaches — vary layout,
tone, and density — and lay them out as a single HTML file
in a grid. Label each with the tradeoff it's making.

代码评审

02 · ANNOTATED DIFF

diff 是空间信息，Markdown 把它压扁了。让 agent 把变更渲染成带边距批注、按严重度配色的 HTML —— 比 GitHub 默认 view 顺。

Help me review this PR by creating an HTML artifact.
Focus on the streaming/backpressure logic. Render the diff
with inline margin annotations, color-code findings by severity.

设计 / 原型

03 · TUNER

动效和交互不能用文字描述 —— 一个带 slider 的临时页面 5 秒讲清楚一段话讲不明白的事。

I want to prototype a new checkout button that does a pop
animation and turns purple. Create a HTML file with sliders
for duration and easing. Give me a copy button to export
the parameters that worked.

报告 / 调研 / 学习

04 · INTERACTIVE EXPLAINER

跨多源综合（代码 + git + Slack + 网页）然后产 explainer，是 Claude Code 比 ClaudeAI / Design 强的地方。

I don't understand how our rate limiter actually works.
Read the relevant code and produce a single HTML explainer:
a token-bucket flow diagram, the 3-4 key code snippets
annotated, and a "gotchas" section at the bottom.

临时编辑器

05 · THROWAWAY UI

有时候在 prompt box 里描述不清想要什么 —— 让 agent 给你做一次性的、purpose-built 的小 UI，最后导出回 prompt。

I need to reprioritize 30 Linear tickets. Make me an
HTML file with each ticket as a draggable card across
Now / Next / Later / Cut columns. Pre-sort them by your
best guess. Add a "copy as markdown" button.

起手式 · 别先去写 skill

06 · JUST PROMPT IT

Thariq 原话："我有点担心大家看完文章就去搞个 /html skill。 虽然有价值，但你不需要做那么多 —— 直接说 "做个 HTML 文件" 或 "做个 HTML artifact"。先 prompt 几次找感觉，再考虑写 skill。"

§ 04 · FAQ

常见的"是不是太……"

点开看 Thariq 的回答（按 + 展开）。

是不是更费 token？
确实更费。但 表达力换来的"被读完"是更大的 ROI。 配合 Opus 4.7 的 1M context，多用的 token 在窗口里几乎感受不到。
HTML 比 Markdown 慢多少？
慢 2–4×。但效果值得。Thariq 原话："This does take longer! But I've found the results are worth it."
HTML 文件怎么打开 / 怎么分享？
浏览器本地直接打开（让 Claude open 它），或者 上传 S3 拿 URL 做 sharable link。
HTML diff 是不是更难做版本控制？
是。这是最大的缺点。 比 Markdown diff 更 noisy、更难 review。Thariq 没有 silver bullet，明确说这条是 tradeoff。
怎么让 HTML 不丑 / 符合公司审美？
frontend design plugin 有帮助。要贴公司 style，让 Claude 扫一遍代码库做一份 design system HTML 当参考， 其他 HTML 文件都引用它。
那 Markdown 你完全不用了吗？
原话："I have honestly stopped using markdown altogether for almost everything, but I'm probably far on the HTML maximalist side of things."
§ 05 · STAY IN THE LOOP

真正让我没切回去的事

Thariq 文章最后一段说得很直白 ——

"I had begun to fear that, by no longer reading plans in depth, I would simply have to leave Claude to make its choices. Instead, I feel more in the loop than ever before."

HTML 表面是输出格式的切换，本质是把人从"读 plan"重新拉回到"看清楚 / 改一下 / 回到 prompt"的循环里。 切了之后才发现 —— 之前那种"放手让 Claude 决定"的焦虑没有了。

三条带走

  1. 直接说 "做个 HTML 文件" / "做个 HTML artifact" —— 别先去写 skill。
  2. 用链接分享 上传 S3 拿一个 URL，同事点开就读，比 .md 附件读完率高 10 倍。
  3. 回灌 prompt 让 HTML 加 "复制为 prompt" 按钮 —— 把 UI 操作的结果直接喂回 Claude，闭环。
